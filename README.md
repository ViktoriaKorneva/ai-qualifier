# AI-квалификатор входящих

Бот, который принимает поток входящих обращений, отвечает на типовые вопросы
по базе знаний клиента, собирает анкету, отсекает нецелевых по правилам,
напоминает о недоделанном шаге и передаёт менеджеру уже готового лида.

> **Учебный прогон.** Клиент «Смена» (сервис подработок) — гипотетический,
> данные придуманы для тренировки. Реального заказчика с такими условиями нет.
> Прототип собран по ТЗ реального заказа с FL.ru как тренировка перед откликом.

## Запуск

```powershell
python run.py               # диалог в консоли
python tests/run_tests.py   # прогон 16 тестовых диалогов
python tests/run_tests.py -v   # то же, с расшифровкой каждого диалога
```

Нужны Python 3.10+, `pyyaml` и `requests`. Модель необязательна: без ключа
бот работает на правилах и базе знаний, свободные вопросы честно уходят человеку.

В диалоге работают служебные команды: `/time 3` сдвигает время на 3 часа
(чтобы показать напоминание, не ожидая три часа), `/quit` завершает и сохраняет лида.

## Что бот умеет

- **Отвечает на вопрос посреди анкеты** и возвращается к тому месту, где прервались.
  Это главное отличие от опросника: человек спрашивает про оплату, когда захочет.
- **Разбирает живые ответы:** «меня зовут Светлана», «2003» вместо возраста,
  телефон в любом формате, «в заречном» вместо «Заречный».
- **Отсекает по жёстким правилам** — вежливо и с объяснением причины.
- **Не выдумывает.** Сначала база знаний, потом модель со строгим запретом
  добавлять факты, потом честное «передам координатору».
- **Уводит человеку** конфликтные темы сразу, на любом шаге.
- **Считает лида:** горячий / тёплый / холодный с прозрачным баллом.

## Архитектура

Всё, что меняется от клиента к клиенту, живёт в конфиге и адаптерах, а не в коде.

```text
clients/smena.yaml     вопросы, тексты, правила, база знаний, скоринг
        │
core/dialog.py         машина состояний — что происходит дальше
core/rules.py          разбор ответов и жёсткие правила
core/knowledge.py      поиск по базе знаний
core/llm.py            единственное место, знающее про поставщика модели
core/models.py         состояние диалога и лид
        │
adapters/channel.py    консоль (Telegram, Авито — новые классы, 3 метода)
adapters/storage.py    CSV (Google Sheets, CRM — то же самое)
```

Перенос к другому клиенту = новый YAML. Перенос в другой канал = новый адаптер.
Ядро при этом не трогается — это и есть путь к коробке.

## Настройка модели

Ключи только в `.env`, никогда в коде и не в репозитории:

```env
AI_TEXT_BASE_URL=https://api.odirouter.ai/v1
AI_TEXT_API_KEY=...
AI_TEXT_MODEL=...
```

Смена провайдера — правка переменной. Интерфейс OpenAI-совместимый,
его понимают все используемые прокси.

Если данные должны остаться в российском контуре, подойдёт YandexGPT: у него
[OpenAI-совместимый эндпоинт](https://yandex.cloud/ru/docs/ai-studio/concepts/openai-compatibility),
поэтому меняется только `AI_TEXT_BASE_URL` и `AI_TEXT_MODEL` — код не трогается.
Примеры строк — в `.env.example`.

## Что осознанно не сделано

- **Нет подключения к Авито.** Их API требует аккаунта продавца и модерации
  приложения. Канал подключается адаптером; логика от этого не меняется.
- **CSV вместо Google Sheets** — интерфейс хранилища уже готов, замена точечная.
- **Напоминание живёт в памяти процесса.** Для продакшена нужен планировщик
  и база: перезапуск сейчас теряет таймеры.
- **Персональные данные.** Бот собирает имя, возраст и телефон — это ПДн.
  На реальном проекте нужны договор поручения с заказчиком, локальные акты
  и российский контур модели. В учебном прогоне данные придуманы.

## Тесты

16 сценариев, половина — про то, как люди пишут на самом деле: путают возраст
с годом рождения, спрашивают своё вместо ответа, уклоняются, грубят.

Два реальных бага были найдены именно тестами:

1. Слово «когда» содержит подстроку «да» — вопрос кандидата засчитывался
   как подтверждение регистрации. Теперь сравнение по словам.
2. «Когда деньги придут» попадало в ответ про размер ставки вместо сроков
   выплаты. Теперь совпадение целой фразой весит больше одиночного слова.
